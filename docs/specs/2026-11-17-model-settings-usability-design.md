# 模型设置易用性与状态一致性设计

日期：2026-11-17

## 范围

1. 添加/编辑模型弹窗限制在视口内，标题和底部操作固定，仅表单区域滚动。
2. 添加与编辑共用表单；编辑时模型 ID 只读，其余配置可修改并持久化。
3. 无搜索条件时保留零模型厂商，提供明确的空状态和添加入口。
4. 模型开关立即反馈，同一厂商串行写入，防止旧响应、列表刷新和旧请求失败覆盖后续操作。

## 弹窗

仅修改模型配置弹窗，不改变公共 Dialog。`DialogContent` 使用 `max-h-[calc(100dvh-2rem)]`、纵向 Flex 和 `overflow-hidden`；头部与底部 `shrink-0`，表单 `min-h-0 flex-1 overflow-y-auto overflow-x-hidden`。表单及输入区域使用 `min-w-0`，避免长内容撑宽。

## 编辑协议

复用 `PatchProviderModels`，不增加新命令。编辑生成 `rename + enable + setFree`：

- `rename` 更新显示名，空显示名回退模型 ID。
- `enable` 更新思考开关、支持 Effort、默认 Effort、图片输入、输出能力、上下文、温度和缓存 Key；不传 `enabled`，保留列表可见性。
- 关闭思考时清空支持 Effort 和默认 Effort；编辑后的 Effort 列表不再包含旧默认值时，也清空默认 Effort。
- 仅免费区值发生变化时发送 `setFree`，无关编辑不得改变原有 `freeLocked` 状态。
- 后端 `enable` 仅更新请求中存在的字段，其他字段不变。

## 空厂商过滤

过滤模型后，无搜索关键词且原始厂商模型总数为零时保留厂商；指定厂商筛选仍始终保留。搜索关键词非空时沿用模型搜索结果。厂商空状态不伪造模型行，仅展示提示和现有添加操作。

## 状态一致性

`ProvidersStore.patchModels` 保留同步乐观更新。每个厂商维护串行 mutation 队列、最近确认快照和待处理操作：

- 新操作先更新可见状态，再入队。
- 成功响应只更新确认快照；可见状态由确认快照重放剩余操作得到。
- 失败只移除失败操作并保留后续操作，同时展示错误；IPC 异常也归一为失败结果，队列不得悬挂。
- 有待处理操作的厂商不被原始列表结果直接覆盖；刷新请求合并，在队列清空后校准。
- 不同厂商的 mutation 不相互阻塞。
